# CLAUDE.md

## 1. 基础约定
1. 设计新类时以简洁高效为原则，不引入多余功能；若需要扩展功能，必须先询问用户确认。
2. **代码注释及文档必须使用中文**。
3. **`print` 输出、图表（`plot`）、UI 文字等面向用户的文本必须使用英文**。

## 2. 提前返回（Early Return）

- 先检查前置条件、参数有效性、错误情况，不满足则立即退出（return / break / continue / 抛异常）
- 主逻辑保持零嵌套，清晰且直接

```python
# 不推荐：主逻辑被嵌套在 if 内
if condition:
    main_process()
else:
    print("Invalid condition")
    return

# 推荐：不满足条件立即返回，主逻辑保持零嵌套
if not condition:
    print("Invalid condition")
    return
main_process()
```

### 多条件检查

多个前置条件逐一检查，避免嵌套金字塔：

```python
if not data:
    raise ValueError("data is required")
if not data.is_valid():
    raise ValueError("invalid data")
if data.is_empty():
    return False
# 所有检查通过，执行主逻辑
data.process()
return True
```

## 3. 编码原则
### 3.1 防止过度设计
1. **只改请求的文件**：用户让改 A，就只改 A，不衍生出 B、C、D；
2. **向后兼容由用户决定**：涉及接口、数据格式等向后兼容问题时，主动询问用户，不自行取舍
3. **解决具体问题**：只解决用户明确指出的问题，不为"未来可能"的需求编码；
4. **简洁优先**：能不加的类就不加；

### 3.2 不要添加未被要求的内容
1. **不添加额外的成员变量**：如用户未要求字段；
2. **严格按需求实现**：用户要求做什么就做什么，不多做一步。

### 3.3 重构代码规则
1. 当你修改一个文件的行数超过 50% 时，触发重构代码；
2. 当你重构代码的时候，不要在原有代码上进行修改，你必须使用 `mv` 将原文件重命名为 `.bak` 备份，然后创建同名新文件完全重写，在验证功能通过后，删除 `.bak` 备份。**必须使用 `mv` 而非 `cp`**，因为 `mv` 后原文件不再存在，强制你从头重写，避免旧代码的干扰。

**执行流程**：
- 步骤1：使用 `mv file file.bak` 将原文件移走（此时 file 不再存在）
- 步骤2：创建新文件 `file` 并完全重写（从头编写，不复制原内容）
- 步骤3：验证功能（运行测试/检查）
- 步骤4：通过则删除 `file.bak`，失败则询问用户如何处理

## 4. 工作流程

- 修改前，简要说明**打算做什么**；
- 修改后，简要说明**改了什么**；
- 遇到不确定的需求，先提问，再动手。
