# 总结 Git 提交历史

总结指定时间范围内的 Git commit 历史，生成工作摘要报告。

## 重要约束

**仅在用户显式调用 `/git_summary` 命令时执行**，不要在该命令文件出现在上下文中时自动执行。

## 使用方法

```
/git_summary [name=用户名] [email=邮箱] [time_since=时间范围]
```

## 参数说明

### name（可选）
指定提交者名称，如 `name=张三`

### email（可选）
指定提交者邮箱，如 `email=zhangsan@example.com`

### time_since（可选）
- 无参数：默认统计过去 7 天
- 相对时间：如 `time_since="2 weeks"`、`time_since="3 days"`
- 具体日期：如 `time_since="2024-01-01"`

**注意**：
- 若未提供 `name` 和 `email`：自动通过 `git config user.name` 和 `git config user.email` 获取当前用户
- 若只提供 `name` 或 `email` 其中一个：使用提供的参数筛选
- 若同时提供 `name` 和 `email`：以 `email` 为准进行筛选

## 使用示例

```
/git_summary                                           # 总结当前用户过去7天的提交
/git_summary name=张三                                  # 总结用户"张三"过去7天的提交
/git_summary email=zhangsan@example.com                 # 总结指定邮箱用户过去7天的提交
/git_summary time_since="2024-01-01"                   # 总结当前用户从2024-01-01至今的提交
/git_summary name=张三 time_since="2 weeks"             # 总结用户"张三"最近两周的提交
/git_summary time_since="3 days"                       # 总结当前用户最近3天的提交
```

## 执行步骤

1. **解析命名参数**：
   - 从命令参数中解析 `name=xxx`、`email=xxx`、`time_since=xxx` 格式的参数

2. **确定目标用户**：
   - 如果未提供 `name` 和 `email`：执行 `git config user.name` 和 `git config user.email` 获取当前用户
   - 如果提供 `email`：使用 `email` 作为 `--author` 参数进行筛选（优先）
   - 如果只提供 `name`：使用 `name` 作为 `--author` 参数进行筛选

3. **确定时间范围**：
   - 如果未提供 `time_since`：默认使用 `--since="7 days ago"`
   - 如果 `time_since` 是相对时间（如 "2 weeks", "3 days"）：转换为 `--since="2 weeks ago"` 格式
   - 如果 `time_since` 是具体日期（如 "2024-01-01"）：直接使用 `--since="2024-01-01"`

3. **获取提交记录**：
   - 使用 `git log` 命令获取符合条件的 commit 列表
   - 格式包含：commit hash、日期、提交信息、修改文件统计

4. **生成摘要报告**（调用大语言模型进行智能总结）：
   - 统计提交总数
   - 将 commit 信息输入大语言模型，按任务/功能维度进行分组总结
   - 识别相关的 commit 并归类到同一任务下
   - 为每个任务生成简洁的描述

5. **输出报告**：
   - 以清晰的格式展示工作摘要
   - 包含时间范围、提交者信息、主要工作内容

## 输出格式示例

```
=== Git 提交摘要 ===
提交者: 张三 <zhangsan@example.com>
时间范围: 2024-01-01 至 2024-01-07 (7天)

共 12 次提交

【工作摘要 - Top 3】
- 完成用户登录模块的开发与联调
- 修复订单页面的核心显示问题
- 优化数据库查询性能，减少响应时间

【任务分组详情】

1. 用户认证模块开发 (5次提交)
   完成用户登录、注册、权限验证等功能的开发
   相关提交:
   - feat: 添加用户认证接口
   - feat: 实现 JWT Token 生成与校验
   - fix: 修复密码校验逻辑
   - refactor: 优化登录流程
   - test: 添加登录单元测试

2. 订单页面 Bug 修复 (3次提交)
   修复订单列表展示异常、金额计算错误等问题
   相关提交:
   - fix: 修复订单列表分页显示问题
   - fix: 修复订单金额精度丢失
   - fix: 修复订单状态同步延迟

3. 数据库性能优化 (2次提交)
   优化慢查询，添加索引提升查询效率
   相关提交:
   - perf: 添加订单表索引
   - perf: 优化用户信息查询 SQL

4. 文档更新 (2次提交)
   更新 API 文档和部署说明
   相关提交:
   - docs: 更新 API 接口文档
   - docs: 更新部署流程说明
```

## 输出格式要求

1. **工作摘要（Top 3）**：
   - 必须放在报告最前面
   - 不超过 3 条，每条 1 行
   - 总结这段时间内投入精力最多的核心工作内容
   - 按重要程度排序

2. **任务分组详情**：
   - **调用大语言模型**对 commit 信息进行分析和归类
   - 将相关的 commit 按任务/功能维度分组（如"用户认证模块开发"、"订单页面 Bug 修复"、"性能优化"等）
   - 每个任务组包含：
     - 任务名称和提交次数
     - 任务描述（一句话概括该任务的目标或成果）
     - 相关 commit 列表（原始提交信息）
   - 任务按提交次数或重要程度排序
   - **不要**按日期罗列每日提交详情

## 注意事项

- 该命令仅读取 Git 历史，不会修改任何代码或提交
- 如果指定用户在该时间段内没有提交，会提示无记录
- `time_since` 支持相对时间（如 `2 weeks`, `3 days`）或具体日期（如 `2024-01-01`）
- 参数使用 `key=value` 格式，等号两侧不要加空格
